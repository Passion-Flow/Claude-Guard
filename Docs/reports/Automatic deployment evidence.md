# Automate Native Setup Without Inventing Assurance

Claude Guard can target **one visible native application, automatic observation, and no API-key fields**, with background enforcement and required macOS authorization. The evidence does **not** establish a complete automatic release path for arbitrary preconfigured Shadowrocket installations. Selected-node security remains unavailable through documented cross-app APIs, and inspected keyless reputation sources do not cover every existing strict admission requirement. A fresh installation must report these gaps and remain blocked. The following contracts describe proposed implementation, not completed product behavior. Research used bounded local metadata and public-address samples; it did not validate the deployment exit or install on a freshly reinstalled Mac.

## One application can coordinate setup, but authorization remains explicit

Package the GUI, native observation components and privileged enforcement helper as one private deliverable. Prefer a signed/notarized **pkg** for installation; a **dmg** can carry it, while a **tgz** needs an equally defined installer and integrity verification. The GUI should detect dependencies, install/register its helper, guide necessary system approvals, run preflight, and display precise blockers without endpoint or provider-key entry. These are implementation requirements; packaging, fresh-install prompts, uninstall/rollback and restart recovery remain untested.

Keep routine discovery in the logged-in user's process and expose only typed, minimal, authenticated observations to root. Administrative authorization for enforcement does not authorize reading another application's protected container. macOS 15+ can require separate privacy approval; Shadowrocket's app-group membership cannot simply be adopted by a different developer. Missing approval means unavailable evidence, not a bypass or a request for broad disk access. Normal Tailscale authentication, when needed, remains a user action. ([Apple app-group access](https://developer.apple.com/documentation/xcode/accessing-app-group-containers.md), [container protection](https://developer.apple.com/documentation/xcode/protecting-local-app-data-using-containers.md))

## Shadowrocket discovery must preserve an unknown-security state

Automatically identify the live signed provider, VPN service/interface, route generation and bounded socket candidates. Validate running-process identity and guard against PID reuse. In the observed installation, numerous remote sockets prevented a unique selected-node inference. **A tuple, port 443, traffic volume or unrelated HTTPS success cannot prove TLS/REALITY verification.** Apple's tunnel-manager API exposes configurations created by the calling app; it is not a Shadowrocket profile API. ([Apple manager contract](https://developer.apple.com/documentation/networkextension/netunnelprovidermanager?language=objc), [running-code identity](https://developer.apple.com/documentation/security/seccodecopyguestwithattributes(_:_:_:_:)))

Model discovery as unavailable, ambiguous, endpoint observed, security unknown, or admitted. A fully automatic secure path needs a supported vendor export binding selection ID/generation, numeric endpoint, transport, verification policy, expected server identity/pins and applicable REALITY metadata to the live provider and socket. Even an export declares configuration rather than proving a live handshake. No such documented export was established. Encrypted profiles and private databases must not be assumed discoverable; preserving the no-field-filling requirement therefore means blocking unsupported installations, not manufacturing a secure declaration. Current admission requires declarations and route binding. ([Existing admission](../../Sources/NodeAdmission.swift), [root admission](../../Daemon/GuardianCore.swift))

## Userspace Tailscale cannot inherit a separate-tunnel exception

The observed Tailscale runs as the user in userspace mode. Read bounded LocalAPI status through its Unix socket; bind each connection to peer UID/PID and process generation, reject redirects/network fallback, and retain only allowlisted fields. Never log raw status containing `AuthURL` or execute user-writable Tailscale binaries as root. Peer identity establishes the answering local process, not trusted provenance for its ad-hoc binary. ([LocalAPI client](https://raw.githubusercontent.com/tailscale/tailscale/main/client/local/local.go), [status schema](https://raw.githubusercontent.com/tailscale/tailscale/main/ipn/ipnstate/ipnstate.go))

**Userspace mode creates no Tailscale tunnel interface.** Preserve the physical-network block and prove its outer traffic follows the approved Shadowrocket path. Do not introduce LAN, DERP or control-plane bypasses. “One peer, SSH only” needs a peer/port-aware broker or equivalent enforcement and packet validation; it cannot be claimed from status or the existing separate-interface exception. ([Official userspace networking](https://tailscale.com/docs/concepts/userspace-networking))

## Keyless evidence supports bounded classification, not universal purity

Proxycheck v3 offers documented anonymous classification at **100 queries/day per querying IP**, but can reject proxy-origin requests. Pin its contract version and budget/cache requests. IPQuery provides a second keyless classifier, although deployment permission and quota remain unresolved before required production use. Neither establishes full residential/abuse/bot coverage. Do not substitute shared credentials inside the client. ([Proxycheck API](https://proxycheck.io/api/), [terms](https://proxycheck.io/terms/), [IPQuery API](https://ipquery.io/developers/api))

Normalize each result with provider/version, query IP/family, path generation, fetch/provider timestamps, status, explicit network type and tri-state category evidence. **Absent, null, unsupported or paid-only flags remain unknown.** False means a provider non-match; non-datacenter does not establish residential. Keep scores separate: the sampled hosting address scored 33 at Proxycheck and zero at IPQuery under different semantics. Never average them or derive a universal purity percentage. ([Proxycheck scoring](https://proxycheck.io/api/), [IPQuery scoring](https://ipquery.io/glossary/risk-score))

Net.Coffee remains a manual diagnostic pending a supported automation contract; its robots policy disallows `/api/`, and risk/geo endpoints do not prove independent vendors. Its “Claude trust” score is not Anthropic's verdict. The other supplied site measures browser-local locale/device heuristics, not IP reputation. ([Net.Coffee script](https://ip.net.coffee/claude/claude-page.js?v=20260916a), [robots policy](https://ip.net.coffee/robots.txt), [locale diagnostic](https://fuck-claude.com/))

Deny on a fresh, bound policy disqualifier. Block on required-source failure, quota, stale evidence, ambiguous endpoint/security, unsupported categories, identity/family/path mismatch or unproved route parity. Release only when every declared requirement is covered. Never retry outside the candidate path to obtain favorable evidence; a website trace does not prove the native API/CLI exit.

## Conclusion

Use the current shared, lower-reputation exit to validate installation mechanics, physical blocking, disconnect/restart handling and denial. Deterministic fixtures can exercise clean, malformed, conflicting, missing-field and quota branches without opening production traffic. **These tests establish enforcement and decision logic, not pristine-exit acceptance.** That acceptance remains unverified until a genuinely qualifying path and complete evidence contract exist; the private bundle must state this limit explicitly.

## Implementation follow-up

Subsequent investigation found a bounded NSKeyedArchive named `ServerManager`. The 0.4 parser maps only its metadata record class and decodes an allowlist of connection/security fields. It matches the opaque selected identifier exactly once, rejects unsupported encryption and duplicate records, resolves domains through interface-bound HTTPS DNS, and corroborates the endpoint against a code-verified running provider. This is compatibility support for an undocumented local format, not a vendor API or proof of the live cryptographic handshake. Missing privacy authorization or changed schemas leave setup unverified. The new keyless policy is explicitly narrower than IPQS: Proxycheck v3 classification and risk flags plus independently observed trace country. The two policies are not represented as equivalent.
