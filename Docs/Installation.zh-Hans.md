# Claude Guard 0.2.6 测试版

Claude Guard 监测 Shadowrocket 系统隧道，在保护生效时拦截普通应用直连。菜单栏显示保护状态和隧道流量。主界面支持配置节点、查看本机事件和导出报告。主应用和离线恢复工具均支持简体中文、英语，以及跟随系统、浅色和深色外观。需使用 macOS 13 或更新版本。

## 安装与验收

1. 打开 DMG，把 **Claude Guard** 和 **Claude Guard Recovery（网络恢复）** 拖进「应用程序」。测试前先确认两个应用都能启动。默认构建使用临时签名，未经 Apple 公证。请从审过的源码构建，再授予本机管理员权限。[Apple 说明](https://support.apple.com/zh-cn/102445)
2. 在 Shadowrocket 连上要使用的节点，在 Guard 点「重新检测」。复制受支持的单节点链接，再点「从剪贴板读单节点」。启用需要通过传输配置检查。「识别端口和协议」可以填写连接信息，传输检查仍需节点链接。节点应能在无需刷新订阅或重新登录的情况下重连。
3. 结束正在运行的任务，关闭 Claude，再点「60 秒试运行」。启用需要在本机授权，并会重置现有过滤状态。等界面显示「整机保护中」后，访问一个普通网页。断开 Shadowrocket，确认网页无法加载新内容，再重连。恢复验证期间，应用应继续被拦截。试运行到期后，拦截继续生效。请在本机操作，断线或试运行到期都可能中断远程管理。
4. 点「持续保护」，测试本地网络断开、切换网络和睡眠唤醒。关闭主界面后，守护继续运行。系统重启后，点「启用上次线路」。更换节点或 VPN 服务时需要重新试运行。
5. 点「恢复网络」可撤销本次规则。主应用不可用时，在「应用程序」打开 **Claude Guard Recovery**，并在本机授权。VPN 仍断开时，撤销规则可能恢复直连。分享报告前请检查其中的内容。

若 0.2.5 或更早版本的保护仍在运行，先关闭 Claude 并在本机恢复网络，再替换两个应用并重新启用保护。

## 防护策略

- **过滤**。默认拦截应用直连，仅在识别到的本地接口保留联网维护和指定节点连接所需的流量。节点例外按连接参数匹配，可访问同一组参数的进程也可能使用该例外。验证通过后，仅在选定隧道内放行受支持的应用流量。
- **传输检查**。节点链接在本机解析，应用保留端点和传输配置依据，丢弃链接原文和凭据。明确关闭传输保护或证书验证的配置会被拒绝。实际握手由 Shadowrocket 和服务端完成。Guard 可以检查导入的配置声明，无法读取实际握手。[Xray 传输文档](https://xtls.github.io/en/config/transport.html)
- **故障恢复**。本地网络不可用时，应用保持拦截，暂停探测和 VPN 重试。联网恢复后，守护继续处理原 VPN 服务。如果服务仍显示已连接、出口探测连续两轮都失败，守护会尝试重启该服务一次。同一隧道和可见路由上连续至少六次检查通过、覆盖至少十五秒后，才放行应用。
- **监测与报告**。隧道速率来自系统计数器。事件在本机保存。出口探测经选定隧道进行，无需采集应用报文内容。

如果 PF 被停用或自有锚点消失，守护仅在周围规则仍兼容时尝试恢复拦截，清理继承的连接状态，再重新验证隧道。规则冲突或恢复失败时，防护状态标记为未确认。外部变更到守护检测之间存在时间窗。

## 验证范围

测试版已通过规则语法检查和守护流程模拟。实际使用前，请在预期使用的网络上验收直连拦截和恢复。测试时请保留本地操作能力，以便使用离线恢复工具。防护只在本次会话生效。系统重启后，重新启用前没有 Guard 拦截。强制结束守护或第三方修改规则都可能影响防护。运行特权守护仍需本机管理员授权。Apple 将 PF 作为系统管理功能。[Apple TN3165](https://developer.apple.com/documentation/technotes/tn3165-packet-filter-is-not-api)
